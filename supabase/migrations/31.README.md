# Migração 31 - Sistema de Manutenção de Veículos

## Visão Geral

Esta migração converte o sistema antigo de manutenções (onde todos os tipos eram aplicados a todos os veículos) para o novo sistema baseado em planos personalizados por veículo.

## Arquivos

### 1. `31.migrate_existing_manutencoes_test.sql` ⚠️ PRÉ-MIGRAÇÃO
**Execute ANTES da migração principal**

Este script analisa os dados existentes e mostra:
- ✅ Total de manutenções realizadas
- ✅ Combinações únicas (veículo + tipo) que serão migradas
- ✅ Lista de veículos que terão planos criados
- ✅ Planos já existentes (possíveis conflitos)
- ✅ Manutenções órfãs (não serão migradas)
- ✅ Preview dos 10 primeiros planos a serem criados

**Uso**:
```bash
psql $DATABASE_URL -f supabase/migrations/31.migrate_existing_manutencoes_test.sql
```

### 2. `31.migrate_existing_manutencoes.sql` 🚀 MIGRAÇÃO PRINCIPAL
**Execute após revisar os resultados do teste**

Este script realiza:
1. Cria planos de manutenção baseados em manutenções realizadas
2. Adiciona comentário na tabela `manutencoes` (agora legada)
3. Cria índices para otimizar consultas históricas
4. Adiciona coluna `migrado_para_novo_sistema` para auditoria
5. Marca manutenções que foram migradas
6. Cria view `historico_manutencoes_completo`
7. Cria função `verificar_manutencoes_nao_migradas()`

**Uso**:
```bash
# IMPORTANTE: Fazer backup primeiro!
pg_dump $DATABASE_URL > backup_pre_migration.sql

# Executar migração
psql $DATABASE_URL -f supabase/migrations/31.migrate_existing_manutencoes.sql
```

### 3. `31.migrate_existing_manutencoes_validate.sql` ✅ PÓS-MIGRAÇÃO
**Execute DEPOIS da migração para validar**

Este script verifica:
- ✅ Quantos planos foram criados
- ✅ Quantas manutenções foram marcadas como migradas
- ✅ Manutenções não migradas (usando função criada)
- ✅ Comparação: manutenções realizadas vs planos criados
- ✅ Integridade: planos com referências válidas
- ✅ Registros na view de histórico
- ✅ Lista de veículos com planos migrados
- ✅ Índices criados
- ✅ Função de verificação funcionando
- ✅ Resumo completo da migração

**Uso**:
```bash
psql $DATABASE_URL -f supabase/migrations/31.migrate_existing_manutencoes_validate.sql
```

## Rollback

Se necessário reverter:

```sql
-- Remover planos criados pela migração
DELETE FROM planos_manutencao_veiculo
WHERE created_at >= '2025-11-27'; -- Ajustar data

-- Remover coluna de marcação
ALTER TABLE manutencoes DROP COLUMN IF EXISTS migrado_para_novo_sistema;

-- Remover view
DROP VIEW IF EXISTS historico_manutencoes_completo;

-- Remover função
DROP FUNCTION IF EXISTS verificar_manutencoes_nao_migradas();

-- Remover índices (opcional)
DROP INDEX IF EXISTS idx_manutencoes_status_data;
DROP INDEX IF EXISTS idx_manutencoes_veiculo_tipo;

-- Restaurar backup
psql $DATABASE_URL < backup_pre_migration.sql
```

## Perguntas Frequentes

### Q: A tabela `manutencoes` será excluída?
**R**: Não! Ela será mantida como histórico. Apenas receberá um comentário indicando que é legada.

### Q: E se eu já tiver planos criados manualmente?
**R**: A migração usa `ON CONFLICT DO NOTHING`, então planos existentes não serão sobrescritos.

### Q: O que acontece com manutenções órfãs?
**R**: Manutenções com `veiculo_id` ou `tipo_manutencao_id` inválidos não serão migradas, mas permanecerão na tabela `manutencoes` para auditoria.

### Q: Posso executar a migração múltiplas vezes?
**R**: Sim! A migração é idempotente. Executar novamente não causará duplicatas.

### Q: Como sei se a migração foi bem-sucedida?
**R**: Execute o script de validação. O total de planos criados deve ser igual ao número de combinações únicas (veículo + tipo) com manutenções realizadas.

### Q: E se houver manutenções não migradas?
**R**: Use a função `verificar_manutencoes_nao_migradas()` para identificá-las. Investigue por que não foram migradas (provavelmente referências inválidas).
